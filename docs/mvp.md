# MVP

## Purpose

The Minimum Viable Product (MVP) defines the smallest useful version of Nomad Guide.

The goal is not to build every planned feature.

The goal is to build a product that already provides real value during a trip.

Every feature included in the MVP should solve a real problem experienced by travellers.

---

# MVP Goal

A traveller can document an entire trip using Nomad Guide.

The application should replace scattered notes and help organize the most important travel information in one place.

---

# Included Features

## Trips

The user can:

- create a trip
- edit a trip
- delete a trip

---

## Places

The user can:

- add places
- edit places
- categorize places

Examples:

- Accommodation
- Restaurant
- Café
- Beach
- Waterfall
- Temple
- Dive Center
- ATM
- Shop
- Viewpoint

---

## Expenses

The user can:

- add expenses
- assign categories
- select currency
- add notes

Examples:

- Accommodation
- Food
- Transport
- Activities
- Diving
- Shopping

---

## Photos

The user can:

- attach photos to places
- attach photos to trips

---

## Notes

The user can create notes for:

- trips
- places

---

## Travel Journal

The user can create daily journal entries.

Each entry may contain:

- date
- text
- photos

---

## Ratings

The user can rate:

- accommodation
- restaurants
- activities
- dive centers
- places

---

# Not Included

The following features are intentionally excluded from the MVP.

## AI

- recommendations
- summaries
- travel planning

---

## Cloud

- synchronization
- user accounts
- backup

---

## Social

- chat
- sharing
- community
- travel partners

---

## Maps

- interactive maps
- route planning

---

## External Integrations

- Booking.com
- Google Maps
- Weather
- Public Transport

These features may be integrated in later versions.

---

# Definition of Success

Version 0.1 is successful if a traveller can:

- document a complete trip
- remember visited places
- keep track of expenses
- attach photos
- write daily notes

without needing multiple different apps.

---

# Design Principles

While building the MVP we follow these principles:

- Build only what is needed.
- Solve real travel problems.
- Keep the application simple.
- Offline First.
- Integrate before reinventing.
- Built by travellers, for travellers.

---

# Future Vision

Everything outside the MVP remains documented but will only be implemented when there is a clear need.

Following the YAGNI principle helps keep the project maintainable and focused.
